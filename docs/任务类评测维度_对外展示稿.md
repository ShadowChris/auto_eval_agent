# 任务类评测维度说明

> 本文面向任务类评测的使用者，用于说明系统“评什么、如何判断、如何归因”。详细判定边界见《任务类评估标准》。

## 1. 评测目标

任务类评测用于判断 Agent 是否真正理解用户需求、完成端侧操作，并向用户准确交付结果。系统联合分析文字或图片 Query、录屏关键帧、可见系统状态和 Agent 最终回复，不仅依据 Agent 的口头声明判定任务完成。

## 2. 评测维度

| 具体评测维度 | 维度描述 | 评测标准 | 规则来源（Correctness / Issue Type） |
|---|---|---|---|
| 响应效率与稳定性 | 评价 Agent 的响应速度及任务过程稳定性。 | 记录首字时延和任务完整时延；检查回答或任务是否中断、是否出现临时服务异常。 | **Correctness**：可归责的任务执行中断对应 `nok`；临时系统异常对应 `others`。<br>**Issue Type**：执行中断、环境或算力异常、外部服务暂时异常。<br>首字时延、完整时延和回答流中断为待接入项。 |
| 任务理解 | 评价 Agent 对用户真实操作意图的理解能力。 | 正确识别生效目标、对象、参数、约束和条件分支；带图 Query 需结合图文理解。 | **Correctness**：理解错误并导致错误执行时对应 `nok`；Query 本身意图不明或要求矛盾时对应 `others`。<br>**Issue Type**：任务结果错误、其他执行问题、任务意图不明确、任务要求矛盾。当前无独立的“意图理解错误”或“多模态识别错误”类型。 |
| 执行路径质量 | 评价 Agent 实际操作路径的正确性、完整性和合理性。 | 操作与 Query 相关，路径正确且关键步骤完整；无明显绕路、重复、反复重试或无关操作。 | **Correctness**：影响任务闭环的路径错误对应 `nok`；不影响结果的轻微问题可保持 `ok`。<br>**Issue Type**：执行中断、三方应用跳转中断、其他执行问题、重复操作、路径冗余、轻微无关步骤、其他轻微问题。 |
| 任务承接与阻塞处理 | 评价 Agent 识别必要外部条件并正确引导用户继续任务的能力。 | 只将真实且无法自主补齐的条件识别为阻塞；明确说明用户需补充的信息或完成的操作，避免静默停滞和不必要澄清。 | **Correctness**：真实阻塞且无更高优先级错误时对应 `no_support`；阻塞前已有独立执行错误时对应 `nok`。<br>**Issue Type**：待用户澄清、缺少前置条件、其他阻塞原因。 |
| 任务完成度 | 评价 Agent 是否真正完成用户要求并形成可验证的结果。 | 完成全部生效目标；最终状态正确且可验证；多目标任务完整闭环，条件任务执行正确分支。 | **Correctness**：全部生效目标闭环对应 `ok`；存在可归责错误对应 `nok`；客观阻塞对应 `no_support`；证据不足或异常对应 `others`。<br>**Issue Type**：应执行目标未执行、任务结果错误、未展示可验证结果。 |
| 融合答复质量 | 评价 Agent 最终回复对实际执行结果的传达质量。 | 准确告知执行结果并与界面状态一致；表达清晰简洁，无语义重复、自相矛盾或内部过程泄露。 | **Correctness**：回复与界面明确冲突，或回复矛盾影响结果交付时对应 `nok`；其他一般质量问题通常不改变 correctness。<br>**Issue Type**：回复与界面不一致、回复语义重复、回复内容自相矛盾、内部过程信息泄露、重复系统卡片。 |

单个 Case 中，除时延使用具体数值外，其他检查项原则上先记录为“是/否”或对应的结构化状态。“准确率”“中断率”“问题率”等仅用于批量 Case 汇总，不作为单题判定字段。

“任务规划”当前建议对外表述为“执行路径质量”。现有评测主要根据录屏关键帧观察实际操作，不应在没有结构化规划轨迹时推测 Agent 的内部规划。

## 3. 结果状态

`correctness` 表示整道任务的最终状态，不由某一个维度分数直接推导。

| 状态 | 对外解释 |
|---|---|
| `ok` | 所有生效目标已正确完成或正确跳过，无需用户继续操作。 |
| `nok` | 存在可归责的理解、执行或结果错误，影响任务闭环。 |
| `no_support` | 任务因必需的用户信息、登录授权、设备条件或活动对象缺失而无法全自动闭环，且不存在优先级更高的执行错误。 |
| `others` | 因结果证据不足、临时系统异常或评测输入问题，无法可靠判定任务结果。 |

示例：任务已成功但存在轻微绕路时，可判为 `ok`，同时降低“执行路径质量”评分并记录“路径冗余”。正确停在必需授权环节时，可判为 `no_support`，但“任务承接与阻塞处理”仍可表现良好。

## 4. 问题归因

`issue_types` 用于说明结果异常或维度扣分的原因，不代替 `correctness`。对于单个 Case，每种 Issue Type 只有“出现/未出现”两种状态，但可以同时命中多个类型；`issue_types[0]` 是决定整体结果的主要根因，其余为其他独立问题或通用质量问题。

| 问题类别 | 代表性 Issue Type | 主要影响维度 |
|---|---|---|
| 执行路径问题 | 重复操作、路径冗余、轻微无关步骤、执行中断、三方应用跳转中断 | 执行路径质量 |
| 任务结果问题 | 应执行目标未执行、任务结果错误、未展示可验证结果 | 任务完成度 |
| 阻塞与交互问题 | 待用户澄清、缺少前置条件、其他阻塞原因 | 任务承接与阻塞处理 |
| 结果反馈问题 | 回复与界面不一致、回复语义重复、回复内容自相矛盾、内部过程信息泄露、重复系统卡片 | 融合答复质量 |
| 系统稳定性问题 | 环境或算力异常、外部服务暂时异常 | 响应效率与稳定性 |
| 评测输入与证据问题 | 视频损坏、录屏不完整、视频无法解析、Query 无法一致核验、评测证据冲突 | 评测有效性门禁 |

当前 Issue Type 中没有独立的“多模态识别错误”或“意图理解错误”标签，相关问题暂时通常表现为“任务结果错误”或“其他执行问题”。如需独立统计理解能力，后续需增加对应的结构化标签。

## 5. 评测有效性门禁

评测前先检查 Query 与录屏是否对应、媒体是否可解析、关键信息是否可见。如果证据不足以评价 Agent，系统输出 `others`，相关维度不评分，避免将数据质量问题误计为 Agent 能力问题。

## 6. 建议对外展示的指标

1. **全自动闭环率**：有效任务中 `ok` 的占比，表示无需用户继续操作即完成任务的比例。
2. **可执行任务成功率**：`ok / (ok + nok)`，用于观察排除真实外部阻塞后的执行能力。
3. **客观阻塞率**：`no_support` 在有效任务中的占比，并区分待澄清、授权登录、设备或对象条件缺失。
4. **异常与不可判定率**：`others` 占比，并拆分为系统异常、评测输入问题和结果证据不足。
5. **质量维度得分**：展示任务完成度、执行路径质量等各维度均分，并支持按任务类型和版本对比。
6. **主问题率**：某 Issue Type 位于 `issue_types[0]` 的 Case 占比，用于统计直接决定整体结果的主要根因。
7. **问题出现率**：某 Issue Type 出现在 `issue_types` 任意位置的 Case 占比，用于观察主要和次要问题的总体分布。

## 7. 当前实现边界

- 当前独立评分维度为“操作完成度”（70%）和“步骤正确性”（30%）。
- 任务理解、阻塞处理和融合答复质量已纳入判定规则或 Issue Type，但尚未分别输出独立分数。
- 当前结果中的 `latency_s` 是评测模型耗时，不是被测 Agent 的首字或任务完整时延；“响应效率与稳定性”需要额外端侧数据后才能对外量化展示。
- 若后续需要精确统计复杂任务的目标完成率，可在不拆分独立 Case 的前提下，增加逐目标的结构化状态和证据输出。
