# 任务类（录屏）评估标准

> 最后同步：2026-09-03
>
> 唯一规则源：`config/skills/operation.yaml`；如与本文不一致，以 YAML 配置为准。
>
> 输出字段：`correctness`、`issue_types`、`rationale`、`is_low_level`，以及评分维度和总分

## 1. 核心原则

1. 基于整个 query 判断，不将复杂任务拆成多个独立 case。
2. 在执行评判前先核验录屏中展示的原始用户 Query 与评测输入 Query；无法一致核验时直接判 `others`，不评价 agent 执行结果。
3. 先识别实际生效目标、目标依赖关系和条件分支，再判断是否闭环。
4. 只要存在影响结果的可归责错误，整体优先判为 `nok`。
5. 没有可归责错误，但受到无法自主补齐的条件阻塞时，判为 `no_support`。
6. 临时环境异常、评测输入异常或未预期场景，判为 `others`。
7. 用户随 Query 提供图片时，图片与文字共同构成任务输入，但图片本身不是 Agent 完成任务的证据；无图片的任务不注入任何图片规则。
8. `issue_types[0]` 必须是决定 correctness 的主要根因；后续元素只记录其他独立问题或通用质量问题。
9. 区分“幂等状态设置”和“依赖活动对象的动作”：前者当前状态已满足可判 `ok`，后者缺少正在运行的对象时判 `no_support`。
10. 不扩大 query 的完成边界：只有功能或页面名称时，可以按打开、查看或展示入口理解；存在多种合理意图且 agent 明确询问时，按待用户澄清判断。
11. 区分查询和动作：合理查询得到“无结果”可以完成查询；恢复、删除、分享等动作缺少目标对象时属于 `no_support`。

### 带图 Query

- 标准输入字段为可选数组 `query_images`；Web 手动上传目前支持单图，数据集导入和后端支持最多 4 张，并按数组顺序传给裁判。结果中的原输入图片预览支持上一张/下一张切换。
- JSONL 使用 `"query_images": ["data/images/example.png"]`；CSV/XLSX 可用 `query_images`、`query_image_path` 或 `attachment_path`，按列顺序取每行首个非空值。`query_images` 可填写单路径或 JSON 数组，后两列作为单图路径使用。
- 用户输入图片用于理解 Query 指代的对象、内容和参数，与 `context`、Agent 自述及录屏关键帧保持独立。
- 只有样本包含用户图片时，裁判 Prompt 才加入图片说明和图片内容；普通无图任务沿用原 Prompt。
- 用户输入图片不能证明任务已经执行或完成，任务完成情况仍由录屏关键帧和 Agent 自述交叉判断。
- `evidence_frames` 只引用录屏关键帧，不把用户输入图片计入帧序号。
- Agent 错误理解图片并操作错误对象或产生错误结果时，复用现有 `任务结果错误`、`其他执行问题` 等 issue type。
- 图片路径不存在、图片损坏或无法解析属于评测输入错误，在模型调用前报错；图片有效但缺少完成任务所需内容时，才可能判 `no_support / 缺少前置条件`。
- 多组评估遇到带图 Query 时按组独立调用，避免用户输入图片混入多组录屏的全局帧编号；无图样本仍可使用联合评估。

## 2. Correctness 定义

| Correctness | 中文含义 | 判定条件 | 典型场景 |
|---|---|---|---|
| `ok` | 任务正确闭环 | 简单任务唯一生效目标完成，或复杂任务所有生效目标完成；无需用户继续操作；条件任务执行正确分支；幂等状态设置的初始状态已满足也算完成。要求读取密码、验证码、私钥等敏感凭据时，明确说明安全原因并拒绝披露也属于正确安全响应。轻微过程问题只记录 issue。 | 设置卡片显示目标开关已生效；查询结果列表或明确空结果已展示；条件不成立时正确跳过；拒绝泄露密码或验证码。 |
| `nok` | 存在可归责执行错误 | 任一必要目标未执行、结果错误、执行中断、第三方跳转中断，或 agent 回复与界面明确冲突。仅缺少可验证结果不再属于可归责错误。复杂任务中任一目标存在独立错误时，整体优先判 `nok`。 | 停在本可继续完成的步骤；多任务明确漏做目标；设置了错误值；没有用户操作指引而静默停在登录页或设置页；回复“无法为你继续操作了”。 |
| `no_support` | 受到客观条件阻塞 | 不存在影响结果的可归责错误，但缺少 agent 无法自主补齐的条件。等待用户场景需要界面、任务执行过程文字或最终回答明确提示用户登录、授权、验证、补充、选择或确认；明确说明缺少完成任务所需的信息并指引用户提供，或声明能力不支持且无可信反证时，也属于 `no_support`。常规设置任务中，单独声称“不支持”以及页面静态隐私说明不构成阻塞。 | 强制权限弹窗等待用户授权；预订前询问必要选择；缺少待处理图片或文本；手机没有 SIM 卡；应用未安装。 |
| `others` | 其他异常或无法可靠归类 | 不存在优先级更高的可归责错误，且因未展示可验证结果、临时环境、算力、外部服务、评测输入或未预期场景无法完成或判断。 | 已尝试或声称完成但画面无法验证结果；回复“小艺算力不够了，请稍后再试”或“遇到一点小问题，请稍后再试”；反馈为“无验证结果”；视频损坏；任务窗口始终未展开；直接证据互相冲突。 |

### 判定优先顺序

在常规判定前先执行 Query 一致性门禁：只读取录屏中明确属于原始用户指令的文字。若录屏 Query 与评测输入 Query 内容不一致，或录屏 Query 未展示、展示不完整、被遮挡、模糊、无法辨认，直接判 `others / 录屏Query无法与输入Query一致核验`，所有维度和总分填 `null`，不再评价 agent 对当前输入 Query 的执行结果。只忽略空格、换行、标点等展示格式差异，不进行同义改写推断；任务执行面板的规划或步骤、工具调用文字和 agent 回复不能代替原始用户 Query。

```text
存在可归责执行错误？ ── 是 ──> nok
          │
          否
          ↓
所有生效目标完成或正确跳过？ ── 是 ──> ok
          │
          否
          ↓
受到无法自主补齐的前置条件阻塞？ ── 是 ──> no_support
          │
          否
          ↓
临时系统、评测输入或未预期异常 ──> others
```

在进入上述判定前，裁判必须先完成阻塞证据门控：逐帧逐字摘录登录、授权、同意、验证、补充、选择或确认等用户指引，再逐字摘录 agent 文本中“无法、缺少、未提供、请提供、请选择、是否、要不要、请确认”等继续任务所需的信息，并区分界面指引、系统流程状态和 agent 自然语言回复。普通“登录”入口、“查看”按钮、“手动操作中”状态、接管或停止控件、加载动画和“已完成”都不是用户指引。流程“超时/终止”通常只表示结果；但录屏仍停留在登录、授权或身份验证页面时，它可以与该页面和最终反馈共同证明任务因等待用户而结束。“无法继续”“请自行操作”“相关工具已返回结果”等泛化终止语，只有同时说明具体能力限制、缺失条件或用户下一步动作时，才能作为阻塞证据。

明确指引还必须检查必要性、因果性和时效性：用户答复确实是继续任务所必需；此前没有理解错误、不相关关键词、错误入口、工具失败或 query 信息充分却重复询问等独立错误；指引在录屏结束时仍未解除并直接导致未完成。先发生可见错误或执行失败后再问用户是否换路径、继续查找、手动处理或上报，不能把错误洗成 `no_support`。必要澄清必须补齐原任务缺少的信息、对象或选择，或者取得登录、授权、下单等助手无法代替用户作出的确认；用户不负责选择 agent 的搜索、导航、工具或补救策略。后续画面已经进入应用内容、搜索结果、商品详情等阻塞后的执行页面时，旧阻塞已经解除，必须重新评价剩余目标，即使后续执行错误或不完整；仅返回桌面或助手界面不算解除。

复杂多任务按实际串行执行链判断。agent 沿合理流程执行到当前步骤后进入真实、必要且仍有效的待澄清，并因此停止整条任务流时，后续尚未开始的目标属于串行中断后果，不单独判遗漏，即使这些目标逻辑上不依赖同一信息。只有阻塞前已经发生可见错误、已有目标声称完成但无证据，或录屏显示阻塞后仍继续执行其他目标时，才分别评价这些目标。

目标独立性按信息依赖判断，不按结果数量机械判断。多个预订目标共享同一行程偏好、多个平台查询共享同一目标对象或搜索词时，可以共同依赖一次用户澄清；已经展示一个航班、酒店或商品候选，不代表用户已经选择并授权预订或下单。自动接听、日程、联系人或地址、机票酒店门票等任务确实缺少必要参数时，可以在打开应用前先询问，不要求先做与闭环无关的表面操作。

## 3. Issue Type 定义

### 3.1 通用质量问题

这些类型可以和任意 correctness 搭配，默认不单独改变 correctness。

| Issue Type | 允许的 Correctness | 定义 |
|---|---|---|
| 内部过程信息泄露 | 全部 | agent 面向用户的最终回复暴露内部推理、检索过程、skill、工具名称或调用过程，例如“我先想想任务规划”“加载某技能”。有非空 answer 时只检查 answer；answer 为空时检查录屏末段明确面向用户展示的最终视觉回答。系统 step info、任务执行面板中的步骤/函数/skill/工具名和流程状态不属于最终回答，不使用本类型。 |
| 回复语义重复 | 全部 | agent 回复前后重复表达相同含义，影响简洁性或阅读体验。 |
| 回复内容自相矛盾 | 全部 | agent 回复内部存在相互冲突的描述；只有影响最终结果理解或内容交付时才应判 `nok`。 |
| 重复系统卡片 | 全部 | 同一任务出现内容相同或高度重复的系统结果卡；只有造成错误结果或副作用时才影响 correctness。 |

### 3.2 `ok` 的轻微问题

| Issue Type | 定义 |
|---|---|
| 重复操作 | 存在不影响最终结果的重复点击或重复执行。 |
| 路径冗余 | 操作路径存在绕路，但最终结果正确闭环。 |
| 轻微无关步骤 | 存在少量无关步骤，但不影响最终结果。 |
| 其他轻微问题 | 任务正确闭环，但存在其他不影响 correctness 的轻微问题。 |

### 3.3 `nok` 的执行问题

| Issue Type | 定义与边界 |
|---|---|
| 应执行目标未执行 | Query 直接要求或条件成立后已生效、具备执行条件的目标没有开始执行；也包括动作型 query 只完成前置查询或内容定位，例如要求播放却仅停在搜索结果卡、详情卡或播放按钮。目标因条件未触发、明确缺少前置条件，或界面、最终回答已经明确等待用户操作时不使用。 |
| 任务结果错误 | 已经执行或交付结果，但最终结果与 query、可见证据或已知条件不一致。不得因为无法外部核验文字事实而使用。 |
| 执行中断 | 没有明确临时系统异常，界面和最终回答也没有用户操作指引，普通任务执行过程停止、卡住、静默超时或异常循环未结束。 |
| 三方应用跳转中断 | 跳转第三方应用后，只有同时满足以下条件时使用：停在普通登录入口、登录页、首页或其他中间状态；界面、任务执行文字和 agent 均无澄清或用户操作提示；agent 最终回答为空；没有因等待用户而超时或终止的反馈；流程静默停止。登录、授权或确认界面存在明确指引时改按“缺少前置条件”判断。 |
| 回复与界面不一致 | agent 面向用户的自然语言回复与录屏中的可见状态明确冲突。系统任务面板中的步骤文案、勾选、“√已完成”“超时，任务终止”等流程状态不属于 agent 回复；必须指出发生冲突的具体自然语言回复。 |
| 其他执行问题 | 已确认存在影响结果的可归责错误，但现有 `nok` 类型无法覆盖。 |

### 3.4 `no_support` 的阻塞问题

这些类型在复杂任务整体因其他目标错误判为 `nok` 时，也可以作为次要 issue。

| Issue Type | 定义与示例 |
|---|---|
| 待用户澄清 | 为继续完成原始任务，界面、任务执行过程文字或 agent 最终回答已发起明确询问，并且确实缺少用户必须补充的信息、对象、选择或确认，或者需要登录、授权、下单等助手无法代替用户作出的确认。确有必填参数时可以先询问，不要求先打开应用；多个目标共享同一对象、搜索词或预订偏好时可共同依赖该澄清。合理搜索无结果后询问修改关键词或放宽条件属于必要澄清；“继续到设置中查找”“换关键词、换入口还是上报”等执行策略询问，以及不相关关键词、错误入口、工具失败或专家经验已确认存在的入口查找失败后的询问，不能覆盖此前可见错误。 |
| 缺少前置条件 | 缺少图片、待处理文本或内容、应用、登录、权限、身份验证、目标对象、硬件、设备能力或助手能力等无法自主补齐的条件。明确说明缺少必要信息并指引用户提供时属于本类型；“无法继续”“请自行操作”等泛化终止语本身不属于明确能力不支持或前置条件说明。可信反证仅限专家经验或当前可见的同一目标成功证据。第三方登录、授权或身份验证页面与明确接管指引，或者与“因等待而超时/终止”的最终反馈共同出现且结束时仍未解除时，可以判本类型；只有普通登录入口或登录页面、三路证据均无澄清提示、agent 最终回答为空、没有等待反馈且流程静默停止时才判 `nok`。 |
| 其他阻塞原因 | 已确认没有可归责执行错误并受到客观阻塞，但不属于待用户澄清或缺少前置条件。 |

### 3.5 `others` 的异常问题

| Issue Type | 定义 |
|---|---|
| 未展示可验证结果 | 有证据表明目标已尝试，或 agent 明确声称完成，但画面没有展示可验证结果，因此无法确认是否完成，主判 `others`。目标完全未执行时使用“应执行目标未执行”并判 `nok`；已观察到错误结果时使用“任务结果错误”并判 `nok`；复杂任务同时存在其他独立错误时，本类型可作为 `nok` 的次要 issue。 |
| 环境或算力异常 | agent 明确说明算力不足、系统繁忙、遇到临时问题或需要稍后重试。 |
| 外部服务暂时异常 | 外部服务临时不可用，重试后可能恢复；稳定的能力不支持应归入“缺少前置条件”。 |
| 视频损坏 | 输入视频内容明确损坏，无法用于评测。 |
| 录屏数据不完整 | 输入的录屏数据本身明确不完整；不能仅因关键帧没有某状态而推测录屏不完整。 |
| 视频无法解析 | 输入视频无法被系统正常解析。 |
| 任务意图不明确 | Query 无法确定具体任务意图。 |
| 任务要求矛盾 | Query 内部要求互相矛盾，无法确定可执行目标。 |
| 输入数据异常 | Query、上下文、视频路径或其他评测输入存在异常。 |
| 录屏Query无法与输入Query一致核验 | 录屏原始用户 Query 与评测输入 Query 内容不一致，或录屏 Query 未展示、展示不完整、被遮挡、模糊、无法辨认，导致无法确认二者对应。只忽略空格、换行和标点等格式差异；不能用任务执行面板的规划或步骤、工具调用文字、agent 回复代替原始用户 Query。命中后所有评分维度和总分填 `null`。 |
| 任务执行窗口未展开 | 任务窗口始终处于缩略状态，过程和结果均不可见，且没有其他证据可供判断。 |
| 评测证据冲突 | 多项直接证据互相冲突，无法可靠确定最终状态。 |
| 未预期场景 | 出现现有 correctness 和 issue type 未覆盖的新场景。 |
| 其他未归类情况 | 已确认应判 `others`，但现有类型无法准确覆盖。 |

## 4. 证据规则

- 卡片、按钮、设置页面、系统状态、任务执行过程和结果页面都可以作为完成证据，关键是是否展示了具体目标状态。
- 设置结果卡直接显示目标开关状态或当前值时，可以作为充分完成证据，无需再次进入完整设置页面。
- query 明确要求开启、关闭、设置、删除、搜索或查询具体结果时，进入相关页面只属于前置准备，必须继续观察对应动作、状态或结果。到达错误页面或只到上一级入口属于可归责未执行，不得降级为证据不足。
- 复杂任务的每个生效目标都必须有对应证据，一个目标的证据不能替代其他目标。
- 只有“正在操作”“已完成”、工具名称、入口页面或 agent 文字声称，不能证明任务完成。
- 不要求展示状态变化前后对比；幂等状态设置的最终状态或初始状态直接满足 query 即可。
- 查询、天气、攻略、推荐、作文和摘要等文字结果不主动进行外部事实核验，但仍需检查是否完成 query、是否遗漏内容，以及是否与录屏、上下文或可信先验冲突。
- 对播放、发送、发布、拨号、创建、分享等包含不可省略核心提交或触发动作的目标，进入应用、跳转目标页、找到对象、展示详情卡或动作按钮、泛化显示“正在操作某应用/已完成”都只是前置准备。录屏结束时仍停在准备状态且没有客观阻塞时，判 `nok / 应执行目标未执行`；只有已经观察到目标专属的直接触发、执行中或执行完成反馈，后续证据又不足以确认最终状态时，才判 `others / 未展示可验证结果`。
- 当前画面只展示列表的一部分，或某一帧没有出现 query 指定对象，不足以证明该对象客观不存在。只有完整搜索后明确显示无结果、穷尽性列表覆盖目标范围，或可信专家经验直接确认缺失时，才能据此判 `no_support`。
- 必须按时间顺序同时检查视觉证据和完整 agent 文本自述，再把两路证据联合判断；不得只看其中一路。明确的用户操作指引可以出现在弹窗、任务执行过程文字或最终回答中，不要求两路证据重复出现同一句话。
- 固定失败文案按完整语义强制映射：“无法为你继续操作了”表示操控执行失败，判 `nok / 执行中断`；“小艺算力不够了，请稍后再试”和“遇到一点小问题，请稍后再试”表示临时资源或服务异常，判 `others / 环境或算力异常`；“无验证结果”判 `others / 未展示可验证结果`。更一般地，只要现有证据只能确认任务曾尝试或声称完成、却无法验证最终结果，且没有独立的漏执行、结果错误、执行中断或回复冲突，均判 `others / 未展示可验证结果`。
- 对未完成目标先判断最后有效状态。判 `no_support` 前必须说明用户必须补充或完成的具体事项、为何不可由助手替代、结束时是否仍未解除，以及此前是否已有独立错误。第三方登录、授权或身份验证页面与明确用户接管指引，或者与因等待而超时、终止的反馈共同出现时，可以判 `no_support`。后续画面已经进入应用内容、搜索结果、商品详情等阻塞后的执行页面时，旧阻塞已经解除，必须重新评价剩余目标。只有普通登录入口或登录页面、三路证据均无澄清提示、agent 最终回答为空、没有等待反馈且流程静默停止时，才判 `nok / 三方应用跳转中断`。query 信息充分时重复询问，或失败后询问换路径、继续查找、手动处理或上报，不属于必要澄清。仅返回桌面或助手界面不证明此前阻塞已经解除。
- 复杂任务按实际串行执行链判断。当前步骤进入真实、必要且仍有效的待澄清并停止整条任务流时，后续尚未开始的目标属于串行中断后果，不单独判遗漏；阻塞前已经发生的错误或无证据完成声明仍需评价。
- 常规系统设置与设备操控默认属于已支持能力；没有真实外部阻塞时，agent 单独声称“不支持/无法执行”不能判 `no_support`。当前界面或专家经验已经直接证明 SIM 卡、必要应用、活动对象等客观条件缺失时，可以据此判 `no_support`，不强制要求 agent 再重复说明。
- 设置页面中的静态隐私说明、帮助文案、风险提示或协议链接本身不属于用户阻塞。只有出现必须由用户完成的授权、登录、身份验证、密码输入、确认或同意交互时，才可据此判 `no_support`；控件仍可直接操作而 agent 未执行时判 `nok`。
- query 只要求查询、搜索、查看或核对时，画面必须展示对应结果列表或查询完成后的“未找到、无记录、暂无结果”，才能完成查询目标。只有 agent 文字声称空结果而没有任何查询过程、状态或结果画面时，判 `others / 未展示可验证结果`；页面仅显示“搜索中/加载中”只证明发起查询，不能证明完成，结束时无结果通常判 `others`，若 agent 同时声称完成则判 `nok / 回复与界面不一致`。query 要求恢复、删除、分享、粘贴、停止或挂断等动作时，没有可恢复对象、目标文件、剪贴板内容或活动对象属于缺少前置条件，不能因为成功进入页面或展示空状态判 `ok`。
- 任务执行面板中泛化的“执行查询”“调用工具”“已完成”等步骤文字只能证明流程曾尝试，不能代替真实查询页面、结果列表、结果卡或明确空结果。
- agent 回复只说“已打开页面”，但画面已经展示 query 要求的信息或完成状态时，只属于回复不够完整，不等于回复与界面冲突；只有回复明确声称与可见状态相反的结果、对象或参数时，才判 `nok / 回复与界面不一致`。
- query 简短或存在多种合理意图时，如果 agent 能明确指出需要用户补充的具体信息并发起可执行的澄清，判 `no_support / 待用户澄清`；只有输入矛盾、损坏或无法形成可执行澄清时才使用 `others / 任务意图不明确`。
- 先确认 query 的原始完成边界。query 本身要求查询、搜索、推荐或列举时，文字或卡片结果可以完成任务；query 要求预订、下单、发送或发布等实际动作时，前置查询和候选列表只是执行过程，随后询问用户选择、补充或确认应判 `no_support / 待用户澄清`，不能按查询任务提前判 `ok`。
- 缺少原目标必需的信息时，提供通用建议、替代答案或完成其他目标不能把任务改判为 `ok`；只要仍需用户补充信息才能给出 query 要求的具体结果，仍判 `no_support`。
- 复杂任务在真实、必要且仍有效的用户阻塞处停止整条串行流程时，后续未开始目标属于阻塞后果，即使逻辑上不依赖同一信息，也不单独标记遗漏。裁判不得假设 agent 应暂停当前步骤后继续其他目标；阻塞前已有独立错误，或画面显示阻塞后流程仍继续时，才分别评价其他目标。
- 条件任务只有实际完成核验并得到无目标、无风险、无人符合等可信结果时，才能按条件不成立正确跳过后续动作。agent 声称无法扫描、无法查询、缺少必要数据或只能检查部分范围时，属于条件尚未核验，应按真实阻塞判 `no_support`，不能把“无法核验”当作“核验结果为空”。

### 4.1 初始状态与动作前置条件

| 指令类型 | 示例 | 当前已经处于目标状态时 |
|---|---|---|
| 幂等状态设置 | 关闭定位、开启蓝牙、设为静音 | 可以直接判 `ok`，因为用户要求的目标状态已经满足。 |
| 依赖活动对象的动作 | 停止播放、暂停下载、挂断电话、取消导航 | 如果没有正在运行的对象，判 `no_support / 缺少前置条件`；不能仅因最终呈现为“未播放、未通话、未导航”而判 `ok`。 |

如果活动对象存在但 agent 没有执行动作，判 `nok`；如果活动对象不存在且 agent 正确说明情况，判 `no_support`。

## 5. 专家经验

专家经验独立维护在 `config/knowledge/operation.yaml`，只记录产品事实；本文件和 `config/skills/operation.yaml` 继续定义这些事实如何映射为评测结论。普通裁判与主席仲裁使用同一已发布版本。

使用边界：只应用与当前任务直接相关的经验；判断能力范围时，专家经验优先于 agent 自述；判断本次执行状态时，以录屏中的直接证据为准。专家经验说明能力受支持，不等于本次任务已经完成；当前录屏存在明确的登录、授权、密码、个人信息或用户澄清阻塞时，也不能因为能力整体受支持就忽略真实前置条件。

常规系统设置与设备操控默认属于已支持能力。录屏没有真实外部前置条件时，agent 拒绝执行或错误声称“不支持”属于 `nok`，不能仅依据该声明判 `no_support`。这一默认能力不覆盖真实的登录、授权、身份验证、必要信息和活动对象缺失。

| 场景 | 统一解释 |
|---|---|
| SIM 卡 | 当前任务类评测手机默认未安装 SIM 卡；涉及电话、短信或移动数据时，SIM 缺失是可信设备条件。 |
| “√已完成” | 只表示任务执行流程或当前步骤结束，不代表用户目标已经完成，也不能单独作为完成证据、agent 回复或回复冲突证据。同一任务面板出现明确确认或选择指引时，应判为等待用户；后续超时不覆盖该根因。 |
| 播放结果 | 搜索结果卡、影视详情卡、播放按钮、普通应用跳转、打开视频应用、模糊的应用加载画面或流程“已完成”只能证明找到内容或准备播放。播放动作已发起必须有播放专属直接信号，例如触发“播放/立即播放”后紧接播放载入、播放器页面或控件，界面明确显示“正在播放/播放中”，或者出现播放进度、暂停按钮。缺少这些信号时判 `nok / 应执行目标未执行`，不能仅因画面跳转或模糊而降级为 `others`；已经观察到播放专属启动信号、但后续证据不足时，才判 `others / 未展示可验证结果`。 |
| 播客生成 | 出现可识别的播客结果卡即视为播客生成目标完成，即使卡片仍显示“生成中”或尚未自动播放。 |
| 文档生成 | Excel 等文档生成耗时较长；出现与 query 要求的文档类型和主题相符、且没有失败状态的文档结果卡，即视为生成目标完成，即使卡片内容仍在生成或尚未提供最终预览。只有“正在生成”文字而没有卡片不能判完成。 |
| 手电筒状态 | 上方同一手电筒状态区域左侧出现手电筒图标、右侧出现“已开启”时，可以作为手电筒已经开启的直接结果证据，无需再展示控制中心开关。 |
| 第三方登录页 | 停在登录、授权或身份验证页面，同时存在明确用户接管指引，或者明确反馈本次任务已因等待而超时、终止时，可以判 `no_support`。只有普通登录入口或登录页面、界面/任务执行文字/agent 均无澄清提示、agent 最终回答为空、没有等待反馈且流程静默停止时，才判 `nok / 三方应用跳转中断`；回复非空不自动等于 `no_support`。 |
| 任务窗口缩略 | 窗口始终没有展开，导致过程和结果完全不可见时，判 `others / 任务执行窗口未展开`。 |
| 录屏工具控件 | 顶部红色计时、录制胶囊、触控提示等属于录屏工具，不是 agent 操作或任务完成证据。 |
| 敏感凭据 | 对要求查询、展示或泄露账号密码、支付密码、验证码、私钥等敏感凭据的任务，明确说明安全或隐私原因并拒绝披露属于正确响应，可判 `ok`。该规则不适用于开启或关闭隐私模式、联系人头像、定位权限等普通系统设置。 |
| 已确认支持的能力 | 常规系统设置与设备操控默认属于助手支持的能力范围；除非存在真实外部阻塞、缺少活动对象，或任务要求读取受保护敏感凭据，否则仅凭“不支持/无法执行”声明不能证明能力缺失。明确能力包括关怀模式、证书与凭据页面、来电播报、自定义应答语、家人共享、隔空手势截屏、隔空传送和语音通话闪光设置。 |
| 字体与显示 | 字体大小由大到小为特大三档、特大二档、特大一档、特大、超大、大、标准、小；键盘字体与系统字体是不同设置项。 |
| 功能前置条件 | 获取屏幕使用情况前需要完成健康使用设备授权；屏幕使用时间管理依赖健康使用设备已开启；唤醒灵敏度设置依赖语音唤醒已开启。 |

## 6. 输出约束

```json
{
  "correctness": "ok|nok|no_support|others",
  "issue_types": ["受控中文问题类型"],
  "rationale": "逐个生效目标说明结果、证据或阻塞，并解释主判定",
  "is_low_level": "yes|no"
}
```

任务类主裁判不再识别或输出执行链路。为兼容旧历史记录，数据 Schema、历史读取和导出仍可保留旧链路字段；新评估不得依据这些兼容字段推断或覆盖 `correctness`。旧链路规则见 [任务类执行链路识别标准（归档）](./任务类执行链路识别标准_归档.md)。

- `nok`、`no_support`、`others` 至少输出一个 issue type。
- `issue_types[0]` 是主要根因，禁止将通用质量问题放在非 `ok` 结果的第一位。
- 简单任务被判 `nok`，且意图清晰、没有客观阻塞并出现明显基础执行错误时，`is_low_level=yes`。
- `ok`、`no_support`、`others` 和复杂多任务固定 `is_low_level=no`。
