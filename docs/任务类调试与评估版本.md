# 任务类调试与评估版本

## 执行模式

任务类单组、多组均支持 `options.execution_mode`，默认 `full`：

| 模式 | 行为 |
| --- | --- |
| `full` | 全流程；有效抽帧自动复用，缺帧则准备视频后评估 |
| `extract_only` | 只准备视频和抽帧，不初始化裁判客户端、不调用分类或评估模型 |
| `evaluate_only` | 严格验证指定帧版本，直接评估；缺帧/损坏不会静默重新下载或抽帧 |

只抽帧结果标记 `evaluation_status=not_evaluated`，没有 `correctness` 或分数，
不参与效果对比及 ok/nok 统计。历史显示“仅抽帧 · 待评估”，结果区展示抽帧状态、数量、
版本标识、预览和 ZIP 下载。任务进度表示所选执行模式的处理完成数量，不代表已经有业务判定。

## 原任务保护

加载历史后，“新建评估版本”折叠区默认收起。展开后选择执行方式、全部有效条目或
勾选条目，并可填写新任务名称，统一通过“创建并启动”启动：

- 复用抽帧进行评估（默认）：创建新 task_id，保留题目 id、原始输入与评估基准时间，
  引用相同帧，采用当前选择的模型和当前已发布标准，独立保存结果、轨迹和导出。
- 重新抽帧：创建新 task_id，清除复制品中的旧帧引用，再生成新抽帧版本；不评估。
- 重新抽帧并评估：创建新 task_id，重新抽帧后评估，范围仍可选择勾选条目。

当前任务的快捷操作与新版本设置分开：

- 只抽帧任务显示“使用这些帧开始评估”：复用全部有效题目的帧创建独立评估任务，
  不受新版本表单的名称或范围影响，原抽帧任务保持不变。缺帧时预检报错，不自动补抽。
- 普通评估任务统一使用逐题结果旁的“重跑选中项”，结果合并回当前任务。
  点击“选择全部失败/未完成项”可跨分页勾选技术失败、未评估以及没有结果的取消/遗漏项，
  排除已移除的题目；nok 不等于技术失败，不会自动选中，也可自行勾选任意题目重跑。

新任务操作不会修改原任务的输入、帧、结果、统计、备注或磁盘历史文件。
原始数据集文件也不改写。来源仍在运行时不允许创建版本，以避免输入状态不稳定。
技术失败重试保留已有行为：有效帧复用，缺帧可在全流程模式重新准备；
严格仅评估任务仍然禁止自动补抽。需要保留不同方案结果时使用新任务，不使用原位重试。

## 抽帧版本与标准快照

帧归档位于 `runs/frame_sets/<frame_set_id>/`，包括图片、时间点元数据和 SHA-256 清单。
新抽帧按生成任务区分版本，即使图片恰好相同，也不会覆盖旧版本。
复用同一版本只新增引用，不重复复制该版本；旧历史首次复用时先校验、复制到独立归档，
不直接依赖可能被旧抽帧缓存机制改写的目录。后续评估校验帧清单、顺序及内容。
当前不自动清理这些受保护帧；删除历史记录也不会删除仍可被其他任务使用的帧归档。
帧不是抵御服务器文件管理员篡改的 WORM 存储；外部改写会被后续校验检测并报错。

评估配置保存在任务 options.evaluation_snapshot：任务类标准、专家知识、维度、
聚合配置、实际使用的三个 Prompt 模板文本及 policy_hash，不含 API Key。
同一任务后续重试继续使用这份标准和模板；新版本读取当前发布的 YAML 标准。
模型选择与 Provider 仍使用原来的配置和切换机制，不在此处新增评估定义。
`evaluation_timestamp` 从来源继承，不以新建时间替换，避免“今天”等上下文漂移。

## 接口

原 `POST /api/eval` 输入输出保持兼容，可选增加 `options.execution_mode`。
`evaluate_only` 的输入必须引用系统生成的有效帧版本，推荐使用以下新版本接口。

`POST /api/eval/{source_task_id}/fork`：

```json
{
  "action": "reuse_frames",
  "execution_mode": "evaluate_only",
  "item_indices": null,
  "dataset_name": "标准V2回测",
  "options": {
    "concurrency": 35,
    "judge_backend": {"provider_id": "example", "model": "example-model"}
  }
}
```

action 为 reuse_frames / refresh_frames。后者只能选择 extract_only / full。
item_indices 为来源任务的零基数组索引，null 表示全部有效条目；原业务 id 始终保留。
预检缺帧、无效范围或非法模式返回 422，来源在运行返回 409；失败不创建新的历史任务。
成功返回新的 task_id、来源 task_id、名称和 execution_mode，后续沿用原历史、SSE、导出接口。
相同帧的两个评估版本可直接通过现有历史对比模块按 id 对齐；只抽帧任务不能参与效果对比。
