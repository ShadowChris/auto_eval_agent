# auto_eval_agent · 任务类（录屏）评测

> 最后更新：2026-09-10。当前运行模式为 `mode=operation`，默认固定使用**终端用户单裁判**。评测语义以 `config/skills/operation.yaml` 为准，人类可读规则见[任务类评估标准](任务类评估标准.md)；抽帧参数与回归基线见[任务类抽帧算法](操作类抽帧算法.md)。

## 一、当前流程

```text
手工录入或导入 JSONL / CSV / Excel
  → 解析、校验并预览待评数据
  → 按题解析视频路径并提取关键帧
  → 终端用户视觉裁判联合 Query、用户图片、关键帧和 Agent 自述判断
  → 输出 correctness、issue_types、维度评分和证据理由
  → SSE 实时展示，并写入历史、统计、报告和导出文件
```

任务类不运行多裁判投票或主席仲裁。底层仍复用通用 `JudgeClient`、调用日志和输出解析能力；Web 中切换 Provider 或模型只替换模型服务，不改变“终端用户”裁判身份。

## 二、输入与路径

JSONL 每行一题，例如：

```jsonl
{"id":"op_alarm_001","query":"设置明天早上7点的闹钟","context":"设备时区为北京时间","video_path":"data/videos/alarm.mp4","answer":"已设置完成","task_start_time":7}
```

| 字段 | 必填 | 说明 |
|---|---:|---|
| `id` | 否 | 稳定题号；追加数据时建议提供，且批次内不可重复 |
| `query` / `question` | 是 | 用户操作意图 |
| `video_path` | 是 | 录屏路径 |
| `context` | 否 | 时间、地点、设备状态等可信背景；任务类不会自动注入当前时间 |
| `answer` / `agent_statement` | 否 | Agent 最终回复，用于与画面交叉验证 |
| `query_images` | 否 | 用户原始输入图片路径数组，最多 4 张；不能单独作为完成证据 |
| `task_start_time` / `task_end_time` | 否 | 执行区间秒数；开始默认 7 秒，结束为空时自动推断 |

Web 支持 `.jsonl`、`.csv`、`.xlsx`、`.xlsm` 和 `.xls` 数据集。导入只解析字段并生成统一预览，可取消勾选不需要评估的题；真正的视频校验和抽帧在“开始评估”后进行，单题失败不阻塞同批其他题。

相对 `video_path` 会在项目根目录和 `OPERATION_VIDEO_ROOTS` 配置的外部根目录中解析。唯一命中时使用该文件；多处同名命中会报歧义，需填写更完整的相对路径或受信目录内的绝对路径。macOS/Linux 多目录用 `:` 分隔，Windows 用 `;` 分隔。

## 三、视觉信息预处理

当前实现版本为 `hybrid-state-v3.1.0`：在任务时间窗内合并 1 FPS 固定采样、FFmpeg scene 变化帧、任务起止帧、首尾窗口受保护采样和视频最终帧，再经过时间合并、UI 状态聚类、短暂弹窗保护和严格图像去重。`max_frames=20` 是普通候选的目标预算，不是硬上限；受保护帧会被强制保留，因此部分录屏最终可能超过 20 帧。最终帧始终保留。

抽帧结果保存在 `runs/videos/imported/<session>/<item>/`，`keyframes.json` 记录算法版本、参数、时间戳和保留原因。算法版本或任务起止时间变化会使缓存失效。实现入口为 `src/auto_eval/media.py::extract_scene_keyframes`。

## 四、裁判与输出

`RubricJudge.score(..., eval_mode="operation")` 将以下内容组成一次多模态评估：

- 原始 Query、可选 Context 和 Agent 自述；
- 可选用户输入图片；
- 按时间顺序排列的录屏关键帧；
- `operation.yaml` 中的证据规则、判定优先级、问题类型和评分锚点；
- `config/knowledge/operation.yaml` 中已发布的产品事实。

主要输出包括：

| 字段 | 含义 |
|---|---|
| `correctness` | `ok`、`nok`、`no_support`、`others` 四分类闭环结论 |
| `issue_types` | 受控问题类型数组；非 `ok` 时首项为决定整体结论的主要根因 |
| `task_type` | 模型按可独立验收结果数量判断 `simple` / `complex` |
| `rubric` / `rubric_reasons` | “操作完成度”“步骤正确性”的分数与理由；证据不足时可为 `null` |
| `is_low_level` | 是否属于用户感知明显、可稳定避免的低级问题 |
| `evidence_frames` / `rationale` | 录屏证据帧和最终理由 |

结果页会单独展示 Agent 自述。任务类主裁判已停止生成执行链路判断；历史和导出中的链路字段仅用于兼容旧结果。

## 五、Provider、并发与限速

评估配置可选择 OpenAI 兼容 Provider、模型和模型请求限速。选择“跟随裁判角色默认配置”时使用 `config/judges.yaml` 中终端用户裁判的连接；选择自定义 Provider 时，本批任务改用所选模型，但仍执行终端用户 Prompt。

- 默认任务并发为 8；并发控制同时在途的题目数。
- 默认请求限速为每 1 秒最多 9 次，可按批次或重跑调整；限速器按 Provider/API 作用域在当前服务进程内共享，并平滑发放请求。
- Provider 配置位于忽略目录 `runs/web_settings/`。API Key 加密保存且不进入历史、导出或调用日志；部署时建议通过 `.env` 固定 `AUTO_EVAL_CREDENTIAL_KEY`。
- 历史快照会记录无密钥的 Provider、模型、配置版本和限速参数，便于回溯。

## 六、历史追加与数据集修订

任务类历史记录支持“追加到历史评估集”。`POST /api/eval` 使用 `submit_mode="append"` 和目标 `task_id`；系统以 `index`、`序号` 或 `id` 等稳定标识检查重复项，并先返回合并预览。重复题可保留旧结果，或用新输入覆盖并仅重跑该题；Query 不一致时必须人工选择。

数据集维护页提供：

- 排除或恢复单题；排除项保留在历史中，但不参与统计和默认导出；
- 下载每次初始或追加批次的原始 JSONL 快照；
- 从最新有效追加批次开始回滚。新增题会被排除，被覆盖题会恢复到追加前版本；初始批次不可回滚。

相关接口：

```text
GET  /api/eval/{task_id}/dataset
POST /api/eval/{task_id}/dataset/items/exclude
POST /api/eval/{task_id}/dataset/items/restore
POST /api/eval/{task_id}/dataset/batches/{batch_id}/rollback
GET  /api/eval/{task_id}/dataset/batches/{batch_id}/export
```

普通任务类单批支持追加与修订；“任务类多组评估（Beta）”不支持这些操作。

## 七、统计、对比与导出

- `GET /api/eval/{task_id}/statistics`：四分类分布、OK 率、覆盖率和按 Case 去重的问题类型统计。
- `GET /api/eval/{task_id}/report`：单批交互报告数据。
- `GET /api/eval/{task_id}/export`：导出 CSV、JSON、JSONL、XLSX、HTML 或关键帧压缩包。
- `POST /api/operation/comparison/analyze`：混合历史结果和上传结果，对比 2～5 组数据。
- `POST /api/operation/comparison/export`：导出对比 XLSX 或离线 HTML。
- `POST /api/eval/single`、`GET /api/eval/single`：按外部 `task_id + item.id` 写入并查询单题，详见[任务类单题评测接口](任务类单题评测接口.md)。

SSE 入口为 `GET /api/eval/{task_id}/stream`。历史和裁判调用明细分别保存在 `runs/web_history/` 与 `runs/judge_calls/YYYY-MM-DD/{task_id}/`。

## 八、已知限制与验证

- 评估只依据采样到的可见证据；极短瞬态、遮挡、模糊画面或录屏外状态可能无法判断。
- `OPERATION_VIDEO_ROOTS` 是路径访问边界，不会把任意外部路径自动视为可信。
- 请求限速是单进程内共享；多进程或多实例部署需要在外层继续做全局限流。
- 当前端侧前后状态采集与视觉结果融合仍处于规划阶段，尚未进入运行链路。

常用验证命令：

```bash
python -m pytest -q tests/test_operation_import.py tests/test_web_append.py \
  tests/test_web_dataset_revision.py tests/test_web_llm_providers.py
```

启动评估台：`python -m auto_eval.web.server`，浏览器访问 `http://localhost:8502`。
