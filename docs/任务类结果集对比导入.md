# 任务类结果集对比导入

在 Web 的“任务类对比分析”中上传已评估结果，可与系统历史批次混合对比。
每个文件对应一个数据组，最多选择五组，第一组为对照组；上传文件不会调用模型重新评估。

## 文件与字段

支持 JSONL、CSV、XLSX、XLS、XLSM。Excel 优先读取“评估结果”，其次为“逐题结果”、
“逐题-任务类”，都不存在时读取第一个工作表。可以直接上传系统导出的 Excel。

以下五列必须存在：

| 字段 | 单元格要求 |
| --- | --- |
| `id` | 非空，组内唯一。建议以文本格式保存，保留前导零。 |
| `query` | 非空。 |
| `correctness` | `ok`、`nok`、`no_support`。兼容旧结果的 `others`，读取时转换为 `no_support`。 |
| `issue_types` | 允许为空，多项使用中文分号分隔。 |
| `rationale` | 非空。 |

`need_review_cate` 为可选列，允许整列缺省或单元格为空；多项使用中文分号分隔。
缺省时按空列表读取，兼容旧评估集；旧 issue_types 中可识别的复核类别仍按原规则迁移。

兼容 `item_id`/`题号`、`操作意图`/`问题`、`完成判定`/`判定`、
`issue_type`/`问题类型`、`需复核类别`、`判定理由` 等已有列名。
JSONL 中评估字段也可放在 `evaluation` 对象中，问题类型与复核类别可使用数组。

其他字段可选；系统识别的附件、回复、视频链接、挂卡、维度及耗时等字段会用于结果展示。
上传记录的所有原始字段另存为 source_data，保留任意业务标签。上传完整的系统 Excel 时，
还会按 ID 和 Query 关联“数据集明细”，优先采用其原始字段，并保留结果表独有的字段。
明细无法唯一关联时提示警告，回退使用结果表的原始行，不按行号猜测。
`metadata.id` 仅用于追溯，不作为对齐键。

## 校验与统计

缺少必需列时拒绝导入并提示列名。存在部分错误行时保留所有行，提示错误行号及原因，
只让有效行参与统计。重复 ID 对应的所有行均排除。没有任何有效记录时拒绝导入。

原生失败结果若带有 `error`，允许没有 correctness 和 rationale 单元格值，
保留原错误并排除统计。原生 Excel“评估结果”中的空评分行同样保留为无效行。

按 `id` 对齐后校验 query；相同 ID 的 query 不一致时排除统计。
原生历史中缺少 ID 的记录继续使用唯一 query 兜底，不改变已有历史兼容规则。

## 来源标签

从系统历史添加的批次标记为“原生评估”（`source_type=history`）；
通过文件上传的结果集标记为“上传结果”（`source_type=upload`），包括重新上传的系统导出文件。
来源按本次进入对比的方式确定，不从文件中的同名字段读取。

结果集卡片、对比页面和 HTML 报告展示来源标签；Excel“对比概览”提供“来源”列。
两种统计口径切换时保留来源标签，统计公式不受标签影响。

## 共享数据集明细导出

对比 Excel 的第一个子表为“逐题横向对比”，第二个为“数据集明细”。
两表都使用两行表头，数据从第三行开始；“对比序号”及数据行顺序完全一致。
序号按本次对比的原始并集从 1 开始生成，不作为新的任务对齐键。

“数据集明细”每题只保存一份原始记录，优先使用对照组数据。仅存在于实验组的题目，
使用首个包含它的实验组记录，并通过“明细来源组”“明细来源数据集”标识来源。
完整保留被选为基准的原始字段，包括 metadata 与任意标签；若原始记录包含 answer、
video_path 等执行相关字段，它们是该来源组的原始值，不代表其他组的执行结果。
原始字段与新增追溯列同名时，以数字后缀保留原始值。

未匹配、重复 ID、失败、待评估及被当前统计口径过滤的记录仍逐行保留，其他组缺题时结果留空。
同一 ID 的 Query 冲突继续按现有规则分行并排除统计，依靠对比序号区分，避免重复 ID 串行。

同题双方都提供 context 或输入图片时，检查共享输入是否一致。差异展示在对齐警告与明细表的
“共享输入差异”列中，基准值不会被覆盖；此提示不自动改变当前统计范围。
缺少可选输入字段不推断为差异；已识别的旧复核类别兼容规则保持不变。

仅上传“评估结果”表时，只能导出文件实际提供的原始字段；此前已导入但未保存原始列的
浏览器结果集需要重新上传文件，才能保留额外标签。
