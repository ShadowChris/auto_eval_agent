# 任务类阶段调度

每题依次执行：下载远程视频（本地路径跳过）→ 探测与抽帧 → 模型评估。
不同题可以同时处于不同阶段，不等待整个批次下载完或抽帧完。

## 并发配置

Web「评估配置 → 阶段并发」可修改视频下载、抽帧、模型评估并发。
点击「应用并保存」免重启生效，当前正在排队的阶段及后续阶段使用新上限；
已经启动的阶段不会被强行中断。三个字段是服务级共享配置，不是当前数据集专属配置。
历史加载、追加和重跑不会恢复历史配置，也不会改变当前服务的上限；
其他浏览器可点「读取当前配置」同步最新值。

保存值原子写入 `runs/settings/operation_pipeline.json`，服务重启后自动恢复，
优先于 `config/operation_pipeline.yaml` 的部署默认值：

```yaml
download_concurrency: 10
extraction_concurrency: 0
model_concurrency: 0
```

接口查询：`GET /api/operation/pipeline-config`，直接返回上述三个字段。
接口更新：`PUT /api/operation/pipeline-config`，JSON 必须包含上述三个整数字段，
返回 `{"ok":true,"config":{...}}`。非法参数返回 422；磁盘写入失败返回 500，
不改变已生效的内存配置。原评估接口无须增加参数，自动使用当前服务配置。
该管理接口沿用评估台现有访问权限，公网部署应在网关设置访问控制。

- 下载：默认每个服务进程最多 10 个；范围 1–128。使用独立下载线程池，
  避免网络读取占满抽帧和历史记录等功能使用的默认线程池。
- 抽帧：默认 0，即不新增独立限制，不表示无限资源。仍受任务总并发、
  Python 默认线程池大小和服务器资源约束。可设为 2、4 等正整数（最多 128）。
  不更改抽帧参数和 FFmpeg 解码线程设置。
- 模型评估：默认 0，不新增独立限制；正整数限制同时进入评估阶段的题目数。
  多组回退评估仍可能在一题内发起多个模型请求，此设置不代表精确的 API 请求并发。
  现有 provider/request_rate_limit 的请求限速与重试规则继续独立生效。

三个上限在同一服务进程内跨批次、追加、单题重跑共享；多进程/多副本部署不共享配额。
Web 的「整体任务并发」对应 `options.concurrency`，接口字段不改名、不改义，
仍是单个批次从准备到评估的整体在途题目上限
（默认 35），因此同时下载数还受在途题目数量限制。用它约束排队帧和临时视频数量，
不引入无限预下载队列。`/api/operation/prepare` 保留原有请求并发参数及返回结构，
并额外服从统一下载/抽帧上限；上传本地视频的抽帧同样遵守抽帧上限。
本版没有磁盘字节配额；本地空间仍应预留在途远程视频与抽帧所需容量。
例如 35 题、每题单视频 100 MiB，保留到评估结束时可能占用约 3.5 GiB 原视频空间，
多组评估还需按各题的视频数量放大；下载的单文件大小限制仍由 remote_video.yaml 控制。

## 生命周期、超时和兼容性

批跑、追加、单题重跑和多组评估复用同一准备服务；已有有效帧时不重复下载/抽帧。
临时原视频不做跨任务缓存，保留至该题终态；下载失败清理半文件，本地用户视频不删除。
多组任务的各组临时视频随该题一起释放。模型失败重试继续复用已准备好的帧。

阶段等待不占工作线程，不计入视频准备执行超时；下载仍有独立网络时间预算，
`video_prepare_timeout_s` 约束下载及抽帧的累计执行等待时间（包括线程池排队），
默认 300 秒。模型阶段等待不计入 `eval_timeout_s`，取得阶段槽后才启动模型计时。
单题总耗时继续覆盖任务准入后的全过程，包含阶段排队，不更改现有导出字段的口径。

取消/超时会通知下载停止；Python 不能强制停止已经运行的同步抽帧线程，
因此该线程实际退出前仍占抽帧槽并持有视频，避免提前删除文件或突破资源上限。
未开始执行的准备工作收到取消后跳过。强制退出残留仍按远程视频模块的启动清理规则处理。

本版只拆分内部服务与资源控制，不新增需要客户端管理临时文件的公开 HTTP 阶段接口。
现有 `/api/eval` 等接口输入输出不变，历史、SSE、取消、追加、重跑、模型切换、
Excel/JSONL 导出、抽帧预览及评估规则不变。单题失败仍记录 `error`，不转成业务 `nok`。
