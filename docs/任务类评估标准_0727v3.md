# 任务类（录屏）评估标准

> 版本：评估0727v3  
> 适用范围：基于操作录屏关键帧、用户 query、context 与 Agent 自述，对整个操控任务进行整体评估。  
> 核心原则：评估实际完成结果，不把“给出教程、表达计划或声称完成”当作真实执行。

## 1. 评估对象与基本原则

系统以整个 query 为一个评估对象，不把复杂 query 拆成多个独立评测 case。

评估前先判断任务形态：

| 任务形态 | 定义 | 示例 |
| --- | --- | --- |
| 简单任务 | 只有一个可以独立验收的最终结果。即使需要多次点击，仍属于简单任务 | 打开蓝牙、设置静音、拍摄一张照片 |
| 复杂多任务 | 包含多个可以分别验收的最终结果，其中一项完成不能代表整个 query 完成 | 打开蓝牙并关闭深色模式 |

任务形态由“可独立验收的结果数量”决定，而不是由点击次数或操作路径长度决定。

### 1.1 当前任务有效时间窗

只评价从当前 query 首次发出或开始执行，到任务完成、失败或录屏结束之间的行为：

- 当前 query 之前的历史聊天、旧任务和旧操作不算本题步骤。
- 任务完成后的复制、滚动、返回或新任务操作，通常不影响当前任务评分。
- 如果完成后的行为改变、撤销或暴露目标状态，则仍应纳入判断。

### 1.2 录屏载体噪声

以下内容默认属于录屏基础设施，不是 Agent 操作：

- 顶部红色录屏计时、录制胶囊和录屏状态图标；
- 触控提示和悬浮控件；
- 与 query 无关的系统时间、电量、网络等常驻状态。

对于“拍视频、录像”任务，顶部录屏红点或计时不能证明相机正在录像。必须看到相机应用内部的停止或暂停按钮、独立录像计时，或者图库中新生成的视频。

## 2. 证据等级

| 等级 | 证据类型 | 典型内容 | 可以证明什么 |
| --- | --- | --- | --- |
| 第1类 | 最终状态强证据 | 目标设置页和开关状态、创建后的条目、已发送或已保存结果、正在播放或录制状态、可直接核验的服务结果 | 可以独立证明目标已经完成 |
| 第2类 | 过程证据 | 自动操作卡片、进度状态、目标入口、操作轨迹 | 可以证明尝试过或支持步骤评分，不能单独证明最终完成 |
| 第3类 | Agent 文字声明 | “已完成”“已打开”“已设置”等回复 | 只能证明 Agent 的自述，不能作为独立完成证据 |

状态变更类任务判为 `right` 或 `partial` 时，必须具有第1类证据。只有过程卡片或 Agent 文字声明时，不能判为完成。

第1类证据不要求一定展示变化前后的对比：

- 最终画面直接显示目标状态，可以证明完成；
- 初始状态已经满足 query 且有画面证据，也可以证明完成；
- 仅有聊天回复声称已完成，不能证明完成。

对于查询、搜索、导航、日程等结果天然以文字或卡片呈现的任务，文字或卡片可以作为结果载体，但必须核对 query 中的实体、条件、数值和结论。关键事实无法从可信来源、画面或查证工具核实时，应判 `unclear`。

## 3. 评分维度

任务类（录屏）当前包含两个一级维度：

| 维度 | 权重 | 关注重点 |
| --- | ---: | --- |
| 操作完成度 | 0.7 | 整个 query 的目标是否完整闭环，最终状态是否正确且可验证 |
| 步骤正确性 | 0.3 | 实际操作路径是否正确、连贯、合理，是否存在冗余或错误步骤 |

总分按权重计算：

```text
总分 = 操作完成度 × 0.7 + 步骤正确性 × 0.3
```

维度分数和 `correctness` 分别判断，不能仅根据总分推导 `correctness`。

## 4. 操作完成度评分依据

### 4.1 评估内容

操作完成度基于整个 query 判断，重点检查：

- 最终状态是否满足整个 query；
- 是否仍需要用户继续操作；
- 简单任务的最终动作是否已经实际执行；
- 复杂多任务中的所有要求是否完成；
- Agent 自述是否与画面一致；
- 初始状态是否已经满足用户要求；
- 状态切换任务是否有独立于 Agent 文字声明的最终状态证据；
- 查询或服务结果是否满足 query 中的实体、条件和关键事实；
- 是否因权限、账号、用户确认、目标选择、必要信息、硬件或设备能力不足而无法完成。

### 4.2 分数标准

| 分数 | 评分依据 | 典型情况 |
| ---: | --- | --- |
| 5分 | 整个 query 完整闭环，或初始状态已经满足；最终状态有独立画面或可核验结果支持；Agent 自述与证据一致 | 设置成功且开关状态清晰；所有子任务均完成 |
| 4分 | 整个 query 已完成且有独立结果证据，但最终回复存在不影响结果确认的轻微瑕疵 | 操作结果正确，但回复略不完整或措辞轻微不一致 |
| 3分 | 已完成主要过程，但简单任务最终动作未执行，或复杂多任务仍有至少一项未完成 | 已进入目标页面但没有保存；多任务只完成其中一项 |
| 2分 | 只完成少量中间过程，最终目标明显未闭环 | 只打开设置首页或进入相关入口 |
| 1分 | 未执行、最终状态错误、执行相反操作，或只有文字声明而没有实际完成证据 | 仅回复“已设置”；打开错误状态；没有相关操作 |

> 注意：操作完成度为3分不代表 `correctness=partial`。如果最终动作未执行或多任务任一目标未完成，`correctness` 仍应判为 `wrong`。

## 5. 步骤正确性评分依据

### 5.1 评估内容

步骤正确性基于当前任务有效时间窗内的实际操作过程判断，重点检查：

- 是否发生了与 query 相关的实际操作；
- 操作路径是否正确；
- 是否缺失关键步骤；
- 是否出现走错、卡住或反复尝试；
- 是否存在可观察到的冗余、重复或无关步骤；
- 合法替代路径、系统自动跳转和关键帧缺失的过渡画面，不应被误判为冗余；
- Agent 文字描述或操作卡片只能证明计划或过程，不能单独证明步骤已经执行完成。

### 5.2 分数标准

| 分数 | 评分依据 | 典型情况 |
| ---: | --- | --- |
| 5分 | 实际路径正确、连贯，没有可观察到的冗余、无关或错误步骤 | 直接进入正确页面并完成设置 |
| 4分 | 存在少量冗余、重复点击或无关步骤，但不影响最终结果 | 中途多进入一次页面，最终仍正确完成 |
| 3分 | 存在明显绕路或多次重试，但整体方向正确 | 多次返回、搜索或尝试后完成主要过程 |
| 2分 | 多次走错路径或操作混乱，只完成少量相关过程 | 反复进入错误页面，只偶尔触达相关入口 |
| 1分 | 路径完全错误、严重偏离，或没有发生与 query 相关的实际操作 | 操作了无关功能；只给文字教程而未执行 |

## 6. Correctness 评判标准

| 判定 | 中文含义 | 必要条件 | 典型场景 |
| --- | --- | --- | --- |
| `right` | 完整闭环 | 简单任务唯一目标完成，或复杂多任务所有目标完成；无需用户继续操作；有第1类证据；自述与画面一致；过程和回复无可观察瑕疵 | 所有目标完成，路径正确且证据充分 |
| `partial` | 结果完成但过程有瑕疵 | 整个 query 的所有结果都已完成并有第1类证据，但存在重复操作、路径冗余、少量无关步骤、非必要重试或轻微回复瑕疵 | 任务完成，但中途绕路或重复点击 |
| `wrong` | 结果未全部完成或执行错误 | 简单任务最终动作未执行；复杂多任务任一目标未完成；仅有文字或过程证据；最终状态错误；严重走错路径、意图偏离或自述冲突 | 只差最后一次保存；多任务只完成一项；声称完成但画面未完成 |
| `unclear` | 无法公平判断 | 缺少必要信息，必须等待用户授权、登录、选择或确认；设备、账号、硬件或应用不具备条件；录屏关键证据缺失；事实无法核验；证据冲突 | 等待权限确认；用户未提供图片；视频损坏；事实结果无法查证 |

### 6.1 Right

满足以下全部要求时判为 `right`：

1. 整个 query 的全部目标已经完成；
2. 用户不需要继续操作；
3. 最终状态具有第1类证据；
4. Agent 自述与画面证据一致；
5. 当前任务有效时间窗内没有可观察到的操作或回复瑕疵。

如果 query 要求的状态在操作前已经满足，且画面可以直接证明，也判为 `right`。

### 6.2 Partial

`partial` 表示“结果全部完成，但过程不够好”，不是“只完成部分任务”。

必须同时满足：

1. 简单任务的唯一目标或者复杂多任务的所有目标均已完成；
2. 每个目标均有第1类完成证据；
3. 存在可观察到的轻微问题，例如：
   - 重复操作；
   - 路径冗余；
   - 少量无关步骤；
   - 非必要重试；
   - 不影响结果确认的轻微回复瑕疵。

任一目标未完成、只差最后一步，或者只有计划、尝试和文字声明时，禁止判为 `partial`。

### 6.3 Wrong

以下情况应判为 `wrong`：

- 简单任务最终动作未执行，即使只差最后一次保存、确认、开启、拍摄或发送；
- 复杂多任务中任意一个明确要求的目标未完成，即使其他目标已经完成；
- 录屏可正常评估，但只有文字声明、操作卡片或口头指导，没有最终状态强证据；
- 最终状态错误或与 query 相反；
- 操作路径严重错误；
- 严重偏离用户意图；
- Agent 自述与界面明显冲突。

`wrong` 表示在样本可评估、客观完成条件具备的情况下，任务没有正确完成。

### 6.4 Unclear

`unclear` 只用于样本缺陷或客观外部条件导致无法公平判断，不是普通未完成的兜底。

适用情况包括：

- query 缺少必要信息；
- 必须等待用户授权、登录、选择或确认；
- 设备、账号、硬件或应用不具备完成条件；
- 视频损坏、抽帧失败或关键时间段客观缺失；
- 查询结果中的关键事实无法核验；
- 画面、回复或其他证据互相冲突。

如果 Agent 已经发起必要的权限请求或安全确认，并明确等待用户操作，最终因用户没有确认而终止，应判 `unclear`。如果 Agent 没有发起本可完成的流程、主动拒绝授权或错误退出，则应判 `wrong`。

## 7. Correctness 判定顺序

建议严格按照以下顺序判断：

```text
确定当前任务有效时间窗
        ↓
是否存在真实的样本缺陷或客观外部阻塞？
        ├─ 是 → unclear
        └─ 否
             ↓
整个 query 的所有目标是否全部完成？
        ├─ 否 → wrong
        └─ 是
             ↓
是否存在重复、绕路、无关步骤或轻微回复瑕疵？
        ├─ 是 → partial
        └─ 否 → right
```

## 8. 常见边界案例

| 场景 | 判定 | 原因 |
| --- | --- | --- |
| 已进入相机录像模式，但红色开始按钮仍可点击 | `wrong` | 最终录像动作尚未执行 |
| 只有“正在操作”“已结束操作”卡片和“已完成”回复 | `wrong` | 没有最终状态强证据 |
| 打开蓝牙并关闭深色模式，但只证明蓝牙已打开 | `wrong` | 多任务任一目标未完成即为 wrong |
| 所有目标完成，但中途重复进入设置页并多次点击 | `partial` | 结果完成，但存在重复或路径冗余 |
| 未找到指定笔记，Agent 询问是否新建 | `unclear` | 需要用户补充决定 |
| Agent 发起必要权限请求，等待用户授权后超时 | `unclear` | 缺少必要用户授权 |
| 照片已经明确选定，但停在可直接保存的最后一步 | `wrong` | 完成条件具备，但最终动作未执行 |
| 初始状态已经满足 query，且画面直接证明 | `right` | 不强制要求发生状态变化 |

## 9. Error Type 规范

只要 `correctness` 不是 `right`，`error_type` 必须为非空标签。

| correctness | 推荐 error_type |
| --- | --- |
| `right` | `null` |
| `partial` | 重复操作、路径冗余、轻微无关步骤、最终回复瑕疵 |
| `wrong` | 仅文字无状态证据、单任务未完成、多任务未全部完成、最终状态错误、操作路径错误、严重意图偏离、自述与界面冲突 |
| `unclear` | 待权限授权、待账号登录、待信息补充、不具备完成条件、录屏证据缺失、事实结果无法核验、证据冲突 |

错误类型应尽量描述主要直接原因。例如已经进入明显错误页面时，优先使用“操作路径错误”，不应只使用宽泛的“单任务未完成”。

## 10. 是否低级

`is_low_level` 只能输出 `yes` 或 `no`。

以下情况固定为 `no`：

- `correctness=right`；
- `correctness=unclear`；
- 任务形态为复杂多任务。

对于 `wrong` 或 `partial`，只有同时满足以下条件才输出 `yes`：

1. query 意图清晰且简单；
2. 不存在权限、信息、账号、硬件等客观阻塞；
3. 出现明显可归责的简单执行错误、严重意图偏离、没有操作却声称完成，或者界面与回复明显不一致。

不能因为结果为 `wrong` 就自动标记为低级。合理但未成功的复杂路径、系统异常和普通路径冗余通常应输出 `no`。

## 11. 输出字段

任务类（录屏）评估的核心输出结构如下：

```json
{
  "task_type": "simple|complex",
  "rubric": {
    "操作完成度": {
      "total": 1,
      "reason": "该维度的证据与评分理由"
    },
    "步骤正确性": {
      "total": 1,
      "reason": "该维度的证据与评分理由"
    }
  },
  "total": 1.0,
  "correctness": "right|partial|wrong|unclear",
  "error_type": "right时为null，其他判定必须填写",
  "is_low_level": "yes|no",
  "rationale": "任务形态、最终状态、步骤证据、自述一致性和最终判定理由"
}
```

## 12. 一致性检查清单

输出前应检查：

- `right` 是否具有具体的第1类最终状态证据；
- `partial` 是否已经完成整个 query 的所有目标；
- `wrong` 是否排除了真正的权限、信息、账号、硬件或录屏阻塞；
- `unclear` 是否确实来自客观阻塞，而不是普通未完成；
- 非 `right` 是否填写了 `error_type`；
- `right` 和 `unclear` 的 `is_low_level` 是否为 `no`；
- 复杂多任务的 `is_low_level` 是否为 `no`；
- 总分是否按照两个维度权重计算；
- `correctness` 是否独立判断，而不是直接由总分推导。
