# 任务类执行链路识别标准（归档）

> 归档日期：2026-09-05
>
> 状态：已停用。本文仅用于追溯旧结果，不能作为当前任务类主裁判的运行规则，也不得注入当前 Prompt。

## 归档原因

旧版本在任务类主评估中同时判断任务正确性和执行链路，链路视觉边界仍不稳定，容易增加 Prompt 负担并干扰正确性判定。当前版本已从 `config/skills/operation.yaml` 和任务类 Prompt 中移除链路标准及输出要求；`correctness`、`issue_types`、维度分和 `is_low_level` 继续独立运行。

数据 Schema、历史读取和导出暂时保留 `execution_routes`、`route_evidence`、`route_rationale`、`route_status`，仅用于兼容旧批跑记录。若后续重新启用链路识别，应作为独立评估器设计、单独验证一致性，不与 correctness 主 Prompt 混合。

## 旧分类定义

| 内部值 | 展示名 | 旧版视觉定义 |
|---|---|---|
| `fast_system` | 快系统 | 系统级快捷能力直接处理任务，出现对应设置卡、状态卡、控制组件或结果；没有结构化 skill 步骤栏和贾维斯操控卡。不能仅因没有步骤栏判为快系统。 |
| `skill` | skill | 出现独立的系统格式技能名、步骤名、函数、工具或任务流程 step info，或出现带步骤数量、可展开过程信息的“✓ 已完成”栏。普通回答中的技能、工具名称或“相关工具已返回结果”不算。 |
| `jarvis` | 贾维斯 | 出现“思考中/任务执行中”“正在操作设置”等操控任务卡、查看/停止/接管控件、彩色操控边框，或“已结束操控，点击查看”等标识。 |
| `other` | 其他 | 明确观察到不属于前三类的链路，包括 QA、检索生成、普通文字回答或其他新形态。 |

## 旧输出约束

- `execution_routes`：按首次出现时间排列的多标签数组，同一种链路只保留一次。
- `route_evidence`：逐链路记录关键帧序号、客观视觉依据和置信度。
- `route_rationale`：只解释链路识别，不与任务完成判定混写。
- `route_status`：`detected`、`uncertain` 或 `insufficient_evidence`。
- 无足够视觉证据时输出空数组和 `insufficient_evidence`，不自动归为 `other`。
- 链路识别不得改变 `correctness`、`issue_types`、维度分或 `is_low_level`。
- 系统格式的 step info 曾作为 skill 证据；“step info 不属于最终 answer、不能据此标记内部过程信息泄露”已迁入当前 issue type 定义，不依赖本归档规则继续生效。
- “✓ 已完成”“已结束操控”只能说明对应流程曾出现或结束，不能单独证明用户目标完成。

## 后续重建设计约束

如需恢复链路能力，建议使用独立 Prompt、独立结构化结果和独立一致性指标；主评估可以读取经过验证的链路结果作为可选观察信息，但不得让链路类型直接决定 correctness。上线前应使用多标签人工数据分别验证严格匹配、micro/macro F1 和对 correctness 的非劣化。
